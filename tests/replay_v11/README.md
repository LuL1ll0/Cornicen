Inputs use the v1 watchlist, ingest, notifier, cycle, restart, pairs,
evaluation_failure and retention_days actions. Timestamps are literal UTC and
non-decreasing, including across isolated cases. Every pending adapter result
must be consumed by a cycle. A restart requires a committed cycle. Expected
assertions reference a cycle or rebaseline command timestamp. A restart takes
a separate snapshot keyed by `(case, t, "after_restart")`; the ordinary
`(case, t)` snapshot retains the pre-restart observation. A state expectation
selects the reopened store with `"snapshot": "after_restart"`. The selector
is valid only at a matching restart; boundary retry-survival checks use it
explicitly. Unqualified expectations, including `alias_episode` T2 and
`late_identity` T3, continue checking the pre-restart state.

The adapter extension is `{"t": "…", "adapter": "fixture_a", "result":
{"resources": […]}}`. Each resource has `path`, HTTP `status`, raw string `body`,
optional `headers`, `transfer_complete`, and `integrity`. Bodies include literal
HTML, blank strings and broken JSON; the harness must not decode or classify
those as advisories. `integrity` describes the transport's check result, not an
applicability answer. No preclassified adapter results are accepted.

Fixture body grammar for the later validator hook:

- An enumeration is a JSON array of raw advisory objects. The export envelope
  has `generation` (publisher generation time) and `advisories`. A retention
  envelope has `advisories`, `retention_hours`, and `coverage_start`. A conditional
  304 has no body; the real validator must obtain the previously validated cache.
- Advisory fields are `id`, `title`, `url`, `published`, `updated`, `products`,
  `cves`, and `evidence`. Products have local `id`, invented `name`, and optional
  exact `version`. Evidence references `product_id`, uses `scheme: "semver"`,
  and may contain `release`, `range`, `fix`, or `first_fixed`. Ranges use
  `introduced`, exclusive `limit`, or inclusive `last_affected`.
- Raw source statuses are `known_affected`, `known_not_affected`,
  `under_investigation`, and `first_fixed`. These are source assertions, not
  expected aggregate classifications. `withdrawn` is an explicit source date.
  `product_groups` contain `id` and `product_ids`; remediations contain `category`
  and `group_ids`. A missing referenced product/group is deliberately invalid.
- Multiple `cves` beside shared evidence do not associate that evidence with
  every CVE. `associations: [{cve, product_id}]` establishes the synthetic explicit
  partition. `identifiers: [{type: "CVE", value: "CVE-2099-0001"}]` establishes an
  explicit identity link. Display links and advisory membership are not links.
  The fixture adapter must map raw fields through real feed validation and
  classification; it must never return the expected states or notifications.

Fixture registration and execution are test-only. `fixture_registry()` returns
fresh descriptors for `fixture_a` at cycle position 1, `fixture_b` at position 6,

   Configure normal outbox delivery to drain each tick, as spec §8 requires.

Each element of a projected row array must have exactly the selected columns.

event keys are lexicographically sorted. Pair state spells the spec result

Digest recipe: canonical JSON is UTF-8, sorted object keys, compact separators,
and unescaped Unicode. A member digest is SHA-256 of its raw fixture advisory
object in that encoding. An accepted manifest is the list of `{source_id,
digest}` rows sorted by source_id then digest. The cursor digest is SHA-256 of
that list in the same encoding. The empty manifest has digest
`4f53cda18c2baa0c0354bb5f9a3ecbe5ed12ab4d8e11ba873c2f11161202b945`.
C0 uses tick `2099-11-03T00:00:00Z` and this empty digest. Isolated variants retain
that prior C0 even though their observation dates are later. Every serialized
expectation contains literal tick and digest values; there are no Cj placeholders.

Pending mechanics use `AssertionCase`, never `unittest.expectedFailure`.
Schema validation and scenario execution run unwrapped. The active notification
comparison is the **entire** expected list with later-task lines removed;
extra actual notifications fail it. Each pending notification separately checks
its exact delivery multiplicity, including case and timestamp. Each pending
state line checks its observation. Only `AssertionError` raised by that check
is reported with `TestResult.addExpectedFailure`. Other exceptions are errors;
a passing pending check is a suite failure saying `lifted early: update lifted_by`.
Active assertions fail normally. The discoverable suite reports one expected
failure per pending line, with an independent run per assertion.

Frozen comparisons use `dump_database`, `project_frozen`, and `assert_additions`.
Projection takes the historical table, column and meta-key sets from the capture,
projects those columns, filters meta keys, and sorts rows using the capture's
canonical ordering; BLOB cells retain lossless hexadecimal. Compare the projected
dump **and exact notification list** separately. The additions check requires
exactly the eighteen allowed tables (including `advisory_support`,
`advisory_shells`, `affected_latches`,
`manifest_members`, and `baseline_members`), all empty
when adapters are ineffective; old columns must remain identical;
only `adapter_schema_version = "1"` may be added to meta. F0 uses
`foundation=False` because its migration is still v0.1.16. Removed tables,
changed old cells, extra tables/columns/meta keys and nonzero latches cannot be
hidden by projection. The F0 provenance test also checks captured source/input

F4 crash replay and disabled-adapter invariance
---------------------------------------------

`FOUNDATION_TASK = 'F4'` activates all oracle assertions. Pending-mechanics
self-tests temporarily select F3b; no oracle line is deleted or re-tagged.
`tests/test_f4.py` compares each uninterrupted oracle with every crash index.
The test-only wrapper patches `Store.transaction` for record savepoints
(`AdapterStore.commit_staged`, `Engine.commit_advisory`, `Engine._isolated`,
`Engine.observe_unknown_advisory`) and alias links (`advisoryidentity.link`).
It interrupts before entry and after successful release. `Store.queue` has no
transaction of its own, so its reachable call sites are wrapped before/after
the enqueue inside the caller's transaction. A BaseException unwinds every
open savepoint, the database is closed/reopened, and interrupted inputs retry.
Setup and restart initialization are outside injection.

Acknowledgement recording (`outbox.deliver`) is interrupted only after its
transaction commits. A crash between external send and durable acknowledgement
is deliberately excluded: v1 guarantees at-least-once delivery, so that window
can duplicate a notification (design spec §1). No production crash hook exists.
Final equality compares every SQLite table (including future additions), not a
selected projection. This includes all eighteen adapter tables, full advisory
JSON (`identity_history` and `facet_next` included), meta, health, events, pairs,
outbox and cursors. No table is excluded. Notifications equal the authored
expected JSONL exactly, including multiplicity and order.

Only these recovery-dependent values are normalized:

- `staged_containers.path`: require `Path(path).is_file()` and SHA-256 of its
  bytes equal to the stored digest before replacing the allocation name with
  that SHA-256. Durable equality therefore also requires the actual content
  digest to equal the uninterrupted run's corresponding source/resource file.
  All other staged columns compare exactly.
- `adapter_retries`: record each production `AdapterStore.retry` call's failure
  tick, incoming attempt count plus one, and returned backoff duration (including
  its actual jitter and retry headers). Require the persisted integer attempt
  count to equal that recorded count and the deadline to equal production
  `stamp(instant(failure_tick) + timedelta(seconds=returned_wait))` exactly;
  the failure tick must be no later than the harness clock. Compare the failure
  tick in place of the jittered deadline. Subtract only retry increments that
  survived rollback of the interrupted action from the attempt count; require

Known limits (v0.2.0)
---------------------

These paths are unreachable while no adapter is effective.

- `safe_path` rejects `:`.
- The fetch-detail JSON blob grows O(N²) on weekly per-record audits; a non-JSON detail drops remembered failures.
- `finish_cycle`'s non-engine branch duplicates v1 `_health`.
- On mixed CVEs, the advisory path skips accept holds, the `epss_crossings` reset and the urgency recompute.
- A different-scheme row gives UNKNOWN. Placeholder rows hard-code `semver`. An introduced-only range is treated as exact.
- `has_identity` re-parses; `has_routing_data` scans `meta` keys by glob.
- An orphaned shell can remain after a withdrawn staged acceptance.
- `reconcile_facets` adds `facets: []`, `facet_next` (and `identity_history` after a withdrawal) to stored advisory JSON.
- The M2 structural test skips the `_retry_records` local apply.
- Crash comparison: the retry normalisation accepts any increase in a persisted attempt count at the crash boundary as an interrupted retry. It does not yet check the increase against the retry calls the harness witnessed, so corruption of the attempt count made during the crash window is not detected. Deadlines, staged files and crossing rows are compared exactly.
- Harness limits: an `AssertionError` inside a callback is indistinguishable from a harness one; `validate_identities` ignores title strings; the `late_identity` restart row asserts nothing new; the generator hard-codes `stale`; 206 scenario reruns; the F1 guard's prior-membership map sees only seeds and earlier raw inputs.


Final-review reference storage
------------------------------

R11 reference captures exceeding 5,000,000 uncompressed bytes use lossless gzip,
compression level 9 and `mtime=0`, with no original filename in the header.
`tools/capture_r11_reference.py --output DIR` selects this encoding automatically;
`tools/test-capture-r11-reference.py` regenerates from the pinned v0.1.16 tree
and compares compressed bytes. The R11 loader accepts JSON and JSON.gz.
`quiet_thirty_days.json` was 61,138,322 bytes; its `.json.gz` is 1,999,732 bytes.
No other reference exceeded 5 MB.

Unmigrated diagnostics
---------------------

Read-only CLI adapter behavior uses the presence of `meta.adapter_schema_version`
as the single migration check. Without it, explain uses the v1 resolver and both
status formats omit adapter additions. Watch check, selftest, healthcheck, replay,
outbox list (including failed), report (text/JSONL), and db backup already use only
v1 tables. The upgrade differential builds a populated database with the pinned
v0.1.16 Store, compares exit status/stdout/stderr for every entry point, and checks
that the database bytes remain unchanged. Diagnostics never migrate it.
